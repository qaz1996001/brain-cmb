# Design: 更新元框架標準為醫療器材與資訊安全標準

## Context

brain-cmb 專案是一個醫療器材軟體專案，需要符合醫療器材軟體開發的國際標準。現有的元框架支援 ISO/IEC/IEEE 29148（需求工程）和 ISO 20816（機械振動監測），但這些標準不足以滿足醫療器材軟體開發的合規性要求。

醫療器材軟體開發需要遵循：
- **品質管理系統**（ISO 13485）
- **軟體生命週期流程**（IEC 62304）
- **風險管理**（ISO 14971）
- **可用性工程**（IEC 62366）
- **資訊安全管理**（ISO 27001，處理敏感醫療資料）
- **AI 風險管理**（ISO/IEC 23894，適用於 AI/ML 醫療軟體）

同時需要為 brain-cmb 專案建立專屬的文件管理系統，以支援符合標準的開發流程。

## Goals / Non-Goals

### Goals
- 更新元框架 regulations 目錄，支援醫療器材軟體開發標準
- 為每個新標準創建合規性範本與指南
- 建立 brain-cmb 專案的文件管理系統結構
- 保持向後相容性（保留 ISO/IEC/IEEE 29148 作為通用需求工程標準）
- 確保新標準範本與現有範本結構一致

### Non-Goals
- 不刪除現有的 ISO/IEC/IEEE 29148 範本（仍為通用標準）
- 不強制移除 ISO-20816 範本（可保留供參考）
- 不在此階段實作具體的合規性檢查工具（僅提供範本與指南）

## Decisions

### Decision 1: 標準範本目錄結構
**決定**：每個標準建立獨立目錄，包含 `compliance-mapping-template.md` 和相關指南文件。

**理由**：
- 與現有 ISO-IEC-IEEE-29148 和 ISO-20816 的結構一致
- 便於維護與擴展
- 每個標準的合規性要求不同，需要獨立的範本

**替代方案考慮**：
- 單一合規性文件包含所有標準：❌ 過於複雜，難以維護
- 僅提供索引，不提供範本：❌ 不符合元框架的目標（提供可用的範本）

### Decision 2: brain-cmb 文件管理系統結構
**決定**：建立標準化的文件管理系統，包含 requirements、design、traceability、compliance、testing 目錄。

**理由**：
- 符合 IEC 62304 對軟體生命週期文檔的要求
- 與元框架的三層文檔架構對應
- 便於與 OpenSpec 變更管理系統整合

**替代方案考慮**：
- 僅使用 OpenSpec specs：❌ 不足以滿足醫療器材標準的文檔要求
- 扁平化結構：❌ 不符合標準對文檔分類的要求

### Decision 3: ISO-20816 範本處理
**決定**：保留 ISO-20816 範本目錄，但從索引中移除，標記為「可選」或「參考用」。

**理由**：
- 向後相容性
- 某些專案可能仍需要機械振動監測標準
- 不影響新標準的導入

**替代方案考慮**：
- 完全移除：❌ 可能影響使用該標準的專案
- 移至 archive：🟡 可考慮，但當前決定保留

## Risks / Trade-offs

### Risk 1: 範本不完整或不準確
**風險**：新標準的合規性範本可能不完整或不符合實際要求。

**緩解措施**：
- 參考官方標準文件與業界最佳實踐
- 提供明確的「待補充」標記
- 允許專案根據實際需求調整範本

### Risk 2: 文件管理系統過於複雜
**風險**：brain-cmb 文件管理系統可能過於複雜，增加維護成本。

**緩解措施**：
- 提供清晰的 README 說明各目錄用途
- 與 OpenSpec 整合，自動化部分文檔更新
- 提供最小化使用指南

### Risk 3: 標準變更影響現有專案
**風險**：更新標準可能影響已使用舊標準的專案。

**緩解措施**：
- 保留 ISO/IEC/IEEE 29148 作為通用標準
- 明確標記新標準為「醫療器材專用」
- 提供遷移指南（如需要）

## Migration Plan

### Phase 1: 更新索引與結構（本提案）
- 更新 regulations 索引
- 創建新標準範本目錄結構
- 建立 brain-cmb 文件管理系統

### Phase 2: 填充範本內容（後續提案）
- 為每個標準創建完整的合規性範本
- 創建指南文件
- 建立範例文件

### Phase 3: 整合與驗證（後續提案）
- 將新標準整合到 OpenSpec 變更管理流程
- 建立合規性檢查清單
- 驗證範本的正確性與完整性

## Open Questions

1. **ISO-20816 範本是否應移至 archive？**
   - 當前決定：保留，但從索引移除
   - 後續可根據使用情況決定

2. **是否需要為每個標準創建詳細的指南文件？**
   - 當前決定：先創建基本範本，後續根據需求擴展

3. **brain-cmb 文件管理系統是否需要與現有程式碼倉庫結構整合？**
   - 當前決定：獨立文件系統，透過 OpenSpec 整合
   - 後續可根據實際需求調整
